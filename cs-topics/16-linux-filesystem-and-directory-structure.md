# Linux Filesystem and Directory Structure

## Linux Directory Hierarchy

```
/
├── bin      → Essential user binaries (ls, cp, mv, grep)
├── boot     → Boot loader files (kernel, grub)
├── dev      → Device files (disks, terminals)
├── etc      → System configuration files
├── home     → User home directories
├── lib      → Shared libraries
├── media    → Mount points for removable media
├── mnt      → Temporary mount points
├── opt      → Optional/third-party software
├── proc     → Virtual filesystem (process/kernel info)
├── root     → Root user's home directory
├── run      → Runtime data (PIDs, sockets)
├── sbin     → System binaries (admin commands)
├── srv      → Service data (web, FTP)
├── sys      → Virtual filesystem (hardware/kernel)
├── tmp      → Temporary files (cleared on reboot)
├── usr      → User programs and data
│   ├── bin      → User commands
│   ├── lib      → Libraries
│   ├── local    → Locally installed software
│   └── share    → Shared data (docs, man pages)
└── var      → Variable data (logs, caches, spools)
    ├── log      → Log files
    ├── tmp      → Persistent temp files
    ├── cache    → Application cache
    └── lib      → State information
```

## Key Directories Explained

### /etc — System Configuration ⭐⭐⭐

Everything that configures the system lives here.

```bash
/etc/
├── passwd          # User accounts
├── shadow          # Encrypted passwords
├── group           # Group definitions
├── hosts           # Static hostname resolution
├── hostname        # System hostname
├── resolv.conf     # DNS configuration
├── fstab           # Filesystem mount table
├── crontab         # System cron jobs
├── ssh/            # SSH server configuration
├── nginx/          # Nginx configuration
├── systemd/        # Systemd service configuration
└── environment     # System-wide environment variables
```

**Interview relevance**: When asked "Where is X configured?", the answer is almost always `/etc/something`.

---

### /var/log — Log Files ⭐⭐⭐

All system and application logs.

```bash
/var/log/
├── syslog          # General system log (Debian/Ubuntu)
├── messages        # General system log (RHEL/CentOS)
├── auth.log        # Authentication events
├── kern.log        # Kernel messages
├── dmesg           # Boot messages
├── nginx/          # Nginx access/error logs
├── mysql/          # MySQL logs
├── journal/        # Systemd journal (binary)
└── application/    # Custom application logs
```

**Critical for troubleshooting**:
```bash
# Real-time log monitoring
tail -f /var/log/syslog

# Find errors in logs
grep -i "error" /var/log/syslog

# Check authentication failures
grep "Failed password" /var/log/auth.log
```

---

### /tmp — Temporary Files

- World-writable (sticky bit set: `drwxrwxrwt`)
- Cleared on reboot
- Used for temporary processing
- Anyone can write, but can't delete others' files

```bash
ls -ld /tmp
# drwxrwxrwt 1 root root 4096 Jan 01 00:00 /tmp
```

```bash
├── elasticsearch/  # Elasticsearch
└── myapp/          # Custom application
```

### /proc — Virtual Process Filesystem ⭐⭐

Not real files — generated by kernel in real-time.

```bash
/proc/
├── 1/              # Process PID 1 (init/systemd)
│   ├── cmdline     # Command that started the process
│   ├── status      # Process status (memory, state)
│   ├── fd/         # Open file descriptors
│   ├── maps        # Memory maps
│   └── environ     # Environment variables
├── cpuinfo         # CPU information
├── meminfo         # Memory information
├── loadavg         # System load
├── uptime          # System uptime
└── net/            # Network information
```

**Extremely useful for Java troubleshooting**:
```bash
# Check what a Java process is doing
cat /proc/<PID>/cmdline | tr '\0' ' '

# Check open file descriptors
ls /proc/<PID>/fd | wc -l

# Check memory details of a process
cat /proc/<PID>/status | grep -i mem

# System memory overview
cat /proc/meminfo

# CPU info
cat /proc/cpuinfo | grep "model name" | head -1
```

---

### /usr — User System Resources

```bash
/usr/
├── bin/        # Most user commands (gcc, python, java)
├── sbin/       # System admin commands (not essential for boot)
├── lib/        # Libraries for /usr/bin and /usr/sbin
├── local/      # Locally compiled/installed software
│   ├── bin/
│   ├── lib/
│   └── etc/
├── share/      # Architecture-independent data
│   ├── man/    # Man pages
│   └── doc/    # Documentation
└── include/    # C/C++ header files
```

## Filesystem Navigation

### Essential Commands

```bash
# Where am I?
pwd                     # Print working directory

# List contents
ls                      # Basic listing
ls -la                  # All files, long format
ls -lh                  # Human-readable sizes
ls -lt                  # Sort by modification time
ls -lS                  # Sort by size

# Navigate
cd /var/log             # Absolute path
cd ..                   # Parent directory
cd ~                    # Home directory
cd -                    # Previous directory

# Directory tree
tree                    # Visual directory tree
tree -L 2              # Limit depth to 2 levels
tree -d                # Directories only
```

## File Operations

### Creating
```bash
touch file.txt                  # Create empty file / update timestamp
mkdir directory                 # Create directory
mkdir -p path/to/nested/dir     # Create nested directories
```

### Copying
```bash
cp source dest                  # Copy file
cp -r source_dir dest_dir       # Copy directory recursively
cp -p file1 file2               # Preserve permissions/timestamps
cp -a source dest               # Archive mode (preserves everything)
```

### Moving / Renaming
```bash
mv old_name new_name            # Rename
mv file /path/to/destination/   # Move
mv -i file dest                 # Interactive (ask before overwrite)
```

### Removing
```bash
rm file                         # Delete file
rm -r directory                 # Delete directory recursively
rm -f file                      # Force (no confirmation)
rm -rf directory                # Force recursive (DANGEROUS)
rmdir empty_directory           # Remove empty directory only
```

## Reading Files

```bash
cat file                    # Display entire file
less file                   # Paginated viewer (q to quit)
more file                   # Simple paginator
head -n 20 file             # First 20 lines
tail -n 20 file             # Last 20 lines
tail -f file                # Follow file in real-time ⭐⭐⭐
wc -l file                  # Count lines
```

### tail -f for Backend Troubleshooting ⭐⭐⭐
```bash
# Watch application logs in real-time
tail -f /var/log/myapp/application.log

# Watch and filter for errors
tail -f application.log | grep -i "error"

# Watch multiple files
tail -f *.log

# Follow with line count
tail -f -n 100 application.log
```

## Disk Space Commands

### df — Filesystem Disk Space
```bash
df -h                       # Human-readable filesystem usage
df -h /                     # Specific filesystem
df -i                       # Inode usage
```

### du — Directory Usage
```bash
du -sh *                    # Size of each item in current dir
du -sh /var/log             # Size of a specific directory
du -h --max-depth=1 /       # Top-level directory sizes
du -ah | sort -rh | head    # Largest files/directories
```

### Important distinction
```
df → How much space is available on the filesystem
du → How much space files/directories are using
```

## Key Interview Questions

**Q: What's the difference between /bin and /usr/bin?**
> `/bin` contains essential binaries needed for boot and single-user mode (ls, cp, cat). `/usr/bin` contains general user commands that aren't essential for minimal boot. On modern systems, `/bin` is often a symlink to `/usr/bin`.

**Q: What is /proc and why is it useful?**
> `/proc` is a virtual filesystem generated by the kernel. It contains real-time information about running processes and system state. Useful for debugging: `/proc/<PID>/fd` shows open files, `/proc/meminfo` shows memory details, `/proc/cpuinfo` shows CPU info.

**Q: Disk is showing 100% full. How do you troubleshoot?**
```bash
df -h                       # Confirm which filesystem is full
du -sh /* 2>/dev/null       # Find which top-level dir is largest
du -sh /var/*               # Drill down
find / -size +100M -type f  # Find large files
# Common culprits: /var/log, /tmp, large application logs
```

**Q: What's the difference between /tmp and /var/tmp?**
> `/tmp` is cleared on reboot. `/var/tmp` persists across reboots. Use `/tmp` for short-lived data, `/var/tmp` for data that should survive a reboot.

**Q: How do you mount a new disk/volume in Linux?**
```bash
# 1. Find the device
lsblk
# 2. Create filesystem (if new)
mkfs.ext4 /dev/xvdf
# 3. Create mount point
mkdir /data
# 4. Mount
mount /dev/xvdf /data
# 5. Persist in fstab
echo "/dev/xvdf /data ext4 defaults 0 0" >> /etc/fstab
```
