# S3 — Simple Storage Service ⭐⭐⭐

## Theory

S3 is object storage — infinitely scalable, highly durable (99.999999999% — 11 nines), and accessible via HTTP. Store files, images, logs, backups, static websites.

---

## Internal Working

### S3 Structure
```
S3
├── Bucket: my-app-uploads (globally unique name)
│   ├── Object: images/photo.jpg
│   │   ├── Key: images/photo.jpg (full path)
│   │   ├── Value: file content (up to 5 TB)
│   │   ├── Metadata: content-type, custom headers
│   │   └── Version ID: (if versioning enabled)
│   ├── Object: documents/report.pdf
│   └── Object: logs/2024/01/access.log
└── Bucket: my-app-backups
```

### Storage Classes

| Class | Use Case | Durability | Availability | Cost |
|-------|----------|-----------|--------------|------|
| Standard | Frequently accessed | 11 nines | 99.99% | $$$ |
| Standard-IA | Infrequent access | 11 nines | 99.9% | $$ |
| One Zone-IA | Non-critical, infrequent | 11 nines | 99.5% | $ |
| Glacier Instant | Archive, instant access | 11 nines | 99.9% | $ |
| Glacier Flexible | Archive, minutes-hours | 11 nines | 99.99% | ¢ |
| Glacier Deep | Long-term archive, 12h | 11 nines | 99.99% | ¢¢ |
| Intelligent-Tiering | Unknown access pattern | 11 nines | 99.9% | Auto-optimized |

### Lifecycle Rules
```
Upload → Standard (30 days) → Standard-IA (90 days) → Glacier (365 days) → Delete
```

## Code

### Spring Boot + S3 Integration

```java
@Service
public class S3StorageService {
    private final S3Client s3Client;
    private final String bucketName = "my-app-uploads";

    public S3StorageService() {
        this.s3Client = S3Client.builder()
            .region(Region.US_EAST_1)
            .build();  // Uses IAM Role credentials automatically
    }

    public String upload(String key, InputStream content, long size, String contentType) {
        s3Client.putObject(
            PutObjectRequest.builder()
                .bucket(bucketName)
                .key(key)
                .contentType(contentType)
                .serverSideEncryption(ServerSideEncryption.AES256)
                .build(),
            RequestBody.fromInputStream(content, size)
        );
        return String.format("https://%s.s3.amazonaws.com/%s", bucketName, key);
    }

    // Generate presigned URL for direct upload from browser
    public String generatePresignedUploadUrl(String key, int expirationMinutes) {
        S3Presigner presigner = S3Presigner.builder().region(Region.US_EAST_1).build();
        PutObjectRequest putRequest = PutObjectRequest.builder()
            .bucket(bucketName)
            .key(key)
            .build();
        PresignedPutObjectRequest presigned = presigner.presignPutObject(r -> r
            .signatureDuration(Duration.ofMinutes(expirationMinutes))
            .putObjectRequest(putRequest));
        return presigned.url().toString();
    }
}
```

### Presigned URL Pattern (Direct Browser Upload)
```
1. Frontend requests upload URL from Spring Boot
2. Spring Boot generates presigned S3 URL (valid 15 min)
3. Frontend uploads directly to S3 (bypasses your server)
4. S3 notifies via event (optional) → Lambda/SQS

Benefits: No file passes through your server → saves bandwidth and CPU
```

## Interview Questions and Answers

**Q: How would you handle file uploads in a Spring Boot application on AWS?**
> For small files (<10MB): Upload through Spring Boot to S3 using AWS SDK. For large files: Generate a presigned URL and let the client upload directly to S3 — this avoids loading your server with file transfer. For very large files (>100MB): Use S3 multipart upload. Store the S3 key in database, serve via CloudFront.

**Q: What's the difference between S3, EBS, and EFS?**
> S3: Object storage, accessed via HTTP API, unlimited size, serverless. Best for files, images, backups. EBS: Block storage attached to a single EC2, like a hard drive. Best for OS, database files. EFS: Network filesystem mounted by multiple EC2 instances simultaneously. Best for shared application data.

**Q: How do you secure S3 buckets?**
> (1) Block public access (default), (2) Bucket policies for access control, (3) Server-side encryption (SSE-S3 or SSE-KMS), (4) Versioning to prevent accidental deletion, (5) Access logging, (6) VPC endpoints for private access, (7) Presigned URLs for temporary access.

---

## Best Practices

1. **Block public access** by default — use presigned URLs for temporary access
2. **Enable versioning** for critical data (protection against accidental delete)
3. **Lifecycle rules** — auto-transition to cheaper storage classes
4. **Server-side encryption** — SSE-S3 (free) or SSE-KMS (auditable)
5. **Use CloudFront** in front of S3 for serving static content globally
6. **Multipart upload** for files > 100MB
7. **Cross-region replication** for disaster recovery
