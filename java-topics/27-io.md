# 27. I/O (Input/Output)

## Theory

Java I/O provides a comprehensive set of APIs for reading and writing data to various sources: files, network connections, memory buffers, and other programs. The original `java.io` package uses a stream-based model with decorator pattern.

### Stream Types

| Category | For | Base Classes |
|----------|-----|-------------|
| Byte Streams | Binary data (images, audio, serialized objects) | `InputStream` / `OutputStream` |
| Character Streams | Text data (supports character encoding) | `Reader` / `Writer` |

### Key Concepts

- **Stream**: An ordered sequence of data flowing from a source or to a destination
- **Byte stream**: Processes data 8 bits at a time
- **Character stream**: Processes data 16 bits (char) at a time, handles encoding
- **Buffering**: Collecting data in a buffer before performing actual I/O (reduces system calls)
- **Decorator Pattern**: Wrapping streams to add functionality (BufferedReader wraps FileReader)

## Internal Working

### I/O Stream Hierarchy

```
InputStream (abstract)
├── FileInputStream         — reads from file
├── ByteArrayInputStream    — reads from byte array
├── BufferedInputStream     — adds buffering
├── DataInputStream         — reads primitive types
├── ObjectInputStream       — reads serialized objects
└── FilterInputStream       — base for decorators

OutputStream (abstract)
├── FileOutputStream        — writes to file
├── ByteArrayOutputStream   — writes to byte array
├── BufferedOutputStream    — adds buffering
├── DataOutputStream        — writes primitive types
├── ObjectOutputStream      — writes serialized objects
├── PrintStream             — System.out is this type
└── FilterOutputStream      — base for decorators

Reader (abstract)
├── FileReader              — reads chars from file
├── BufferedReader          — adds buffering + readLine()
├── InputStreamReader       — bridge: byte stream → char stream
├── StringReader            — reads from String
└── FilterReader            — base for decorators

Writer (abstract)
├── FileWriter              — writes chars to file
├── BufferedWriter          — adds buffering
├── OutputStreamWriter      — bridge: char stream → byte stream
├── PrintWriter             — formatted text output
├── StringWriter            — writes to String
└── FilterWriter            — base for decorators
```

### How Buffering Works

```
Without buffering (FileInputStream):
Program → read() → System Call → Disk → 1 byte → Program
Program → read() → System Call → Disk → 1 byte → Program
... (one system call per byte = very slow)

With buffering (BufferedInputStream):
Program → read() → Buffer (8KB in memory) → returns 1 byte
Program → read() → Buffer → returns 1 byte (no system call!)
... (buffer empty)
Program → read() → System Call → Disk → 8KB → Buffer → 1 byte
(one system call per 8KB = much faster)
```

### Decorator Pattern in I/O

```
Goal: Read text lines from a file efficiently

FileInputStream fis = new FileInputStream("data.txt");     // raw bytes from file
InputStreamReader isr = new InputStreamReader(fis, "UTF-8"); // bytes → chars
BufferedReader br = new BufferedReader(isr);                  // adds buffering + readLine()

Decorator chain:
  BufferedReader
    └── wraps InputStreamReader
          └── wraps FileInputStream
                └── reads from file on disk
```

```

──────────                    ───────────────
InputStream  ──────→  InputStreamReader  ──────→  Reader
```

## Code

### Reading/Writing Bytes (FileInputStream/FileOutputStream)

```java
import java.io.*;

public class ByteStreamDemo {
    
    // Copy a file byte by byte (slow - for demonstration)
    public static void copyFileSlow(String src, String dest) throws IOException {
        try (FileInputStream fis = new FileInputStream(src);
             FileOutputStream fos = new FileOutputStream(dest)) {
            
            int byteRead;
            while ((byteRead = fis.read()) != -1) { // -1 = end of stream
                fos.write(byteRead);
            }
        } // auto-close both streams
    }
    
    // Copy a file with buffer (fast)
    public static void copyFileFast(String src, String dest) throws IOException {
        try (FileInputStream fis = new FileInputStream(src);
             FileOutputStream fos = new FileOutputStream(dest)) {
            
            byte[] buffer = new byte[8192]; // 8KB buffer
            int bytesRead;
            while ((bytesRead = fis.read(buffer)) != -1) {
                fos.write(buffer, 0, bytesRead);
            }
        }
    }
    
    // Using BufferedInputStream/BufferedOutputStream
    public static void copyFileBuffered(String src, String dest) throws IOException {
        try (BufferedInputStream bis = new BufferedInputStream(new FileInputStream(src));
             BufferedOutputStream bos = new BufferedOutputStream(new FileOutputStream(dest))) {
            
            byte[] buffer = new byte[8192];
            int bytesRead;
            while ((bytesRead = bis.read(buffer)) != -1) {
                bos.write(buffer, 0, bytesRead);
            }
        } // BufferedOutputStream flushes on close
    }
}
```

### Reading/Writing Text (Reader/Writer)

```java
import java.io.*;

public class CharStreamDemo {
    
    // Read file line by line
    public static void readTextFile(String path) throws IOException {
        try (BufferedReader reader = new BufferedReader(new FileReader(path))) {
            String line;
            while ((line = reader.readLine()) != null) {
                System.out.println(line);
            }
        }
    }
    
    // Write text to file
    public static void writeTextFile(String path, List<String> lines) throws IOException {
        try (BufferedWriter writer = new BufferedWriter(new FileWriter(path))) {
            for (String line : lines) {
                writer.write(line);
                writer.newLine(); // Platform-independent line separator
            }
        }
    }
    
    // Append to file
    public static void appendToFile(String path, String text) throws IOException {
        try (FileWriter writer = new FileWriter(path, true)) { // true = append mode
            writer.write(text + System.lineSeparator());
        }
    }
    
    // Read with specific encoding
    public static String readWithEncoding(String path, String charset) throws IOException {
        StringBuilder sb = new StringBuilder();
        try (BufferedReader reader = new BufferedReader(
                new InputStreamReader(new FileInputStream(path), charset))) {
            String line;
            while ((line = reader.readLine()) != null) {
                sb.append(line).append("\n");
            }
        }
        return sb.toString();
    }
}
```

### DataInputStream/DataOutputStream (Primitive Types)

```java
import java.io.*;

public class DataStreamDemo {
    
    public static void writePrimitives(String path) throws IOException {
        try (DataOutputStream dos = new DataOutputStream(
                new BufferedOutputStream(new FileOutputStream(path)))) {
            dos.writeInt(42);
            dos.writeDouble(3.14159);
            dos.writeBoolean(true);
            dos.writeUTF("Hello Java"); // Modified UTF-8
            dos.writeLong(System.currentTimeMillis());
        }
    }
    
    public static void readPrimitives(String path) throws IOException {
        try (DataInputStream dis = new DataInputStream(
                new BufferedInputStream(new FileInputStream(path)))) {
            // Must read in SAME ORDER as written
            int intVal = dis.readInt();
            double doubleVal = dis.readDouble();
            boolean boolVal = dis.readBoolean();
            String strVal = dis.readUTF();
            long longVal = dis.readLong();
            
            System.out.printf("int=%d, double=%.5f, bool=%s, str=%s, long=%d%n",
                intVal, doubleVal, boolVal, strVal, longVal);
        }
    }
}
```

### Try-with-Resources

```java
import java.io.*;

public class TryWithResourcesDemo {
    
    // Java 7+ : Automatic resource management
    public static void modernApproach(String path) throws IOException {
        try (BufferedReader reader = new BufferedReader(new FileReader(path))) {
            String line = reader.readLine();
            System.out.println(line);
        }
        // reader.close() called automatically, even if exception occurs
    }
    
    // Multiple resources
    public static void copyFile(String src, String dest) throws IOException {
        try (InputStream in = new FileInputStream(src);
             OutputStream out = new FileOutputStream(dest)) {
            in.transferTo(out); // Java 9+
        }
    }
    
    // Java 9+ : Effectively final variables
    public static void java9Style(String path) throws IOException {
        BufferedReader reader = new BufferedReader(new FileReader(path));
        // reader is effectively final, can be used directly
        try (reader) {
            System.out.println(reader.readLine());
        }
    }
    
    // Custom AutoCloseable
    static class DatabaseConnection implements AutoCloseable {
        public DatabaseConnection() { System.out.println("Connection opened"); }
        public void query(String sql) { System.out.println("Executing: " + sql); }
        @Override
        public void close() { System.out.println("Connection closed"); }
    }
    
    public static void customResource() {
        try (DatabaseConnection conn = new DatabaseConnection()) {
            conn.query("SELECT * FROM users");
        } // close() called automatically
    }
}
```

### PrintWriter for Formatted Output

```java
import java.io.*;

public class PrintWriterDemo {
    
    public static void writeFormatted(String path) throws IOException {
        try (PrintWriter pw = new PrintWriter(new BufferedWriter(new FileWriter(path)))) {
            pw.println("Report generated: " + java.time.LocalDateTime.now());
            pw.println("─".repeat(50));
            pw.printf("%-20s %10s %10s%n", "Name", "Age", "Salary");
            pw.printf("%-20s %10d %10.2f%n", "Alice", 30, 75000.50);
            pw.printf("%-20s %10d %10.2f%n", "Bob", 25, 62000.00);
            pw.println("─".repeat(50));
            
            // Check for errors (PrintWriter doesn't throw IOException on write)
            if (pw.checkError()) {
                System.err.println("Error occurred during writing");
            }
        }
    }
}
```

```java
import java.io.*;

public class ByteArrayStreamDemo {
    
    // In-memory stream (useful for testing)
    public static byte[] processInMemory(byte[] input) throws IOException {
        ByteArrayOutputStream baos = new ByteArrayOutputStream();
        
        try (ByteArrayInputStream bais = new ByteArrayInputStream(input);
             DataInputStream dis = new DataInputStream(bais)) {
            
            DataOutputStream dos = new DataOutputStream(baos);
            // Transform data
            while (dis.available() > 0) {
                int value = dis.readInt();
                dos.writeInt(value * 2); // Double all integer values
            }
        }
        
        return baos.toByteArray();
    }
}
```

### Reading from Console

```java
import java.io.*;
import java.util.Scanner;

public class ConsoleReadingDemo {
    
    // Using BufferedReader (classic approach)
    public static void readWithBufferedReader() throws IOException {
        BufferedReader reader = new BufferedReader(new InputStreamReader(System.in));
        System.out.print("Enter name: ");
        String name = reader.readLine();
        System.out.println("Hello, " + name);
    }
    
    // Using Scanner (more convenient)
    public static void readWithScanner() {
        Scanner scanner = new Scanner(System.in);
        System.out.print("Enter age: ");
        int age = scanner.nextInt();
        scanner.nextLine(); // consume newline
        System.out.print("Enter city: ");
        String city = scanner.nextLine();
        System.out.printf("Age: %d, City: %s%n", age, city);
    }
    
    // Using Console (handles passwords)
    public static void readWithConsole() {
        Console console = System.console();
        if (console != null) {
            String user = console.readLine("Username: ");
            char[] password = console.readPassword("Password: ");
            // Process credentials
            java.util.Arrays.fill(password, ' '); // Clear password from memory
        }
    }
}
```

## Dry Run

### BufferedReader.readLine() Execution

```
File content: "Hello\nWorld\n"
BufferedReader buffer size: 8192 chars

Step 1: reader.readLine() called
  → Buffer is empty, triggers fill()
  → Reads up to 8192 chars from underlying stream
  → Buffer now contains: ['H','e','l','l','o','\n','W','o','r','l','d','\n']
  → Scans buffer for '\n' or '\r'
  → Found '\n' at index 5
  → Returns "Hello" (without newline)
  → Buffer position advances past '\n'

Step 2: reader.readLine() called
  → Buffer still has data: ['W','o','r','l','d','\n']
  → No system call needed!
  → Scans for '\n'
  → Found at index 5
  → Returns "World"

Step 3: reader.readLine() called
  → Buffer is empty
  → Triggers fill() → underlying stream returns -1 (EOF)
  → Returns null (signals end of file)
```

## Complexity

| Operation | Without Buffering | With Buffering |
|-----------|-------------------|----------------|
| Read 1 byte | 1 system call | Amortized: 1/(buffer size) system calls |
| Read N bytes | N system calls | N/8192 system calls |
| Write 1 byte | 1 system call | Batched until flush |
| File copy (1 MB) | ~1M system calls | ~128 system calls (8KB buffer) |

**Rule of thumb**: Always buffer I/O operations. The overhead of buffering is negligible compared to the cost of system calls.

## Real Project Usage

### 1. Reading Configuration File

```java
public class ConfigLoader {
    private final Map<String, String> properties = new HashMap<>();
    
    public void load(String path) throws IOException {
        try (BufferedReader reader = new BufferedReader(new FileReader(path))) {
            String line;
            while ((line = reader.readLine()) != null) {
                line = line.trim();
                if (line.isEmpty() || line.startsWith("#")) continue;
                
                int equalSign = line.indexOf('=');
                if (equalSign > 0) {
                    String key = line.substring(0, equalSign).trim();
                    String value = line.substring(equalSign + 1).trim();
                    properties.put(key, value);
                }
            }
        }
    }
    
    public String get(String key) {
        return properties.get(key);
    }
}
```

## Interview Questions and Answers

### Q1: What is the difference between byte streams and character streams?
**A**: Byte streams (`InputStream`/`OutputStream`) handle raw binary data 8 bits at a time — used for images, audio, serialized objects. Character streams (`Reader`/`Writer`) handle text data with encoding awareness — they convert bytes to characters using a charset (UTF-8, etc.). Character streams are preferred for text files.

### Q2: What is the Decorator Pattern in Java I/O?
**A**: Java I/O uses decorator pattern extensively. Each stream class adds functionality by wrapping another stream. For example: `BufferedReader` wraps `InputStreamReader` wraps `FileInputStream`. Each layer adds capability (buffering, encoding, file access) without modifying others. This allows flexible composition.

### Q3: What is try-with-resources?
**A**: Try-with-resources (Java 7+) automatically closes resources that implement `AutoCloseable`. Resources declared in the `try()` parentheses are guaranteed to be closed when the block exits, even if exceptions occur. Closing happens in reverse declaration order. This prevents resource leaks.

### Q4: Why should we always use buffering?
**A**: Each read/write without buffering triggers a system call (kernel transition), which is expensive (~1000x slower than accessing RAM). Buffering collects data in memory and performs I/O in larger chunks, dramatically reducing system calls. Default buffer is typically 8192 bytes.

### Q5: What is the difference between flush() and close()?
**A**: `flush()` forces buffered data to be written to the underlying stream but keeps the stream open. `close()` first flushes the stream, then releases the system resources (file handle, socket, etc.). After close(), no more operations are possible.

### Q6: FileReader vs InputStreamReader?
**A**: `FileReader` uses the platform's default charset and provides no way to specify encoding. `InputStreamReader` accepts a charset parameter, giving you control over encoding. In production, always use `InputStreamReader` with explicit charset (usually UTF-8) to avoid platform-dependent behavior.

## Follow-up Questions and Answers

### Q: What is System.in, System.out, System.err?
**A**: 
- `System.in` — `InputStream` reading from console (stdin)
- `System.out` — `PrintStream` writing to console (stdout)
- `System.err` — `PrintStream` for error output (stderr)

They can be redirected: `System.setOut(new PrintStream(new FileOutputStream("log.txt")))`.

### Q: What happens if you don't close a stream?
**A**: Resource leak. The file handle or socket remains open. OS has limited file handles (typically 1024-65535). Accumulating unclosed streams eventually causes `Too many open files` errors. GC may close them via finalizer, but this is unreliable and delayed.

## Common Mistakes

| Mistake | Problem | Fix |
|---------|---------|-----|
| Not closing streams | Resource leak | Use try-with-resources |
| Not buffering | Extremely slow I/O | Wrap with BufferedXxx |
| Using FileReader without specifying charset | Platform-dependent encoding | Use InputStreamReader with charset |
| Reading data in wrong order with DataInputStream | Corrupt data | Read in same order as written |
| Ignoring return value of read(byte[]) | May read fewer bytes than buffer size | Use the returned count |
| Using PrintWriter/PrintStream without checking errors | Silent failures | Call checkError() |

---

## Best Practices

1. **Always use try-with-resources** — Guarantees cleanup even with exceptions
2. **Always buffer** — BufferedReader/BufferedWriter or buffered byte streams
3. **Specify charset explicitly** — Use `StandardCharsets.UTF_8` rather than platform default
4. **Use transferTo() for stream copying** — Java 9+ InputStream.transferTo(OutputStream)
5. **Prefer NIO.2 for file operations** — `Files.readString()`, `Files.readAllLines()` are simpler
6. **Close outer stream only** — Closing the outermost decorator closes all inner streams
7. **Don't swallow IOException** — Log it, rethrow it, or handle it meaningfully

---

## Production Considerations

- **File handle limits**: Monitor open file descriptors in production. Use `lsof` (Linux) or handle monitoring tools.
- **Large files**: Don't read entire file into memory. Process line by line or use memory-mapped files (NIO).
- **Encoding issues**: Always use UTF-8 unless there's a specific reason not to. Mismatched encoding causes garbled text (mojibake).
- **Thread safety**: I/O streams are NOT thread-safe. Synchronize externally if shared between threads.
- **Network I/O**: Set timeouts. Blocking I/O without timeouts can hang threads forever.
